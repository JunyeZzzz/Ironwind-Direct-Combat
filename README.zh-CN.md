# 铁风执刃（Ironwind: Hands-On Combat）

铁风执刃是由 **cjy233** 独立维护的自由控制战斗 Mod，当前版本为 **v121**。它把直接移动、越肩/第一人称镜头、方向攻击、方向格挡、近距 E 交互和中文设置页整合到同一套 V 模式中。

历史代码基础来自 [Direct Control for Kenshi](https://github.com/smokefoolius/Kenshi-Direct-Control) v1.5.0；项目依法保留上游著作权并沿用 GPL-3.0，但当前产品、发布和维护身份统一为“铁风执刃 / Ironwind: Hands-On Combat”。完整边界见 [NOTICE.md](NOTICE.md)。目标环境是 Kenshi 1.0.65、RE_Kenshi 0.3.5 和 64 位游戏进程。

## 安装与启用

运行目录：`Kenshi/mods/IronwindCombat/`。

1. 安装并启用 RE_Kenshi。
2. 将完整 `IronwindCombat` 文件夹放入 `Kenshi/mods/`。
3. 启动器中只勾选 `IronwindCombat.mod`。
4. 不要同时勾选原 `WASDCombatPlugin.mod`，两者会加载同名 DLL 和重复钩子。

运行时必须至少包含：

- `WASDCombatPlugin.dll`
- `WASDCombatPlugin.ini`
- `RE_Kenshi.json`
- `IronwindCombat.mod`
- `Settings.zh-CN.tsv`
- `materials/` 下的材质/着色器资源

## 操作

| 输入 | 功能 |
|---|---|
| `V` | 开关直接控制；开启时进入越肩镜头和手动战斗 |
| `W/A/S/D` | 移动；攻击或格挡时速度上限为平时的 20% |
| 按住左键并移动鼠标 | 持续选择攻击方向；人物暂不播放蓄势动画 |
| 松开左键 | 锁定当前方向并攻击 |
| 选向时按右键 | 取消待发攻击；手动格挡模式下立即按当前方向格挡 |
| 移动鼠标后按住右键 | 手动格挡模式按预览方向格挡；自动格挡模式仍由按住右键发出请求，但方向由原版 AI 选择 |
| 攻击命中判定后按住右键 | 取消剩余后摇并进入格挡；命中前不可取消 |
| `E` | 与附近、视野内自动选中的目标交互并打开该目标的原版菜单；不会切换常驻模式。键盘战斗配置下仍是攻击键 |
| `F` | 在越肩与第一人称之间切换；`P` 不再使用 |
| 鼠标滚轮 | 调整越肩距离；最近端进入第一人称，向外滚回越肩 |
| `Z`／`X` | 完全保留 Kenshi 原版的 1×／5×游戏速度，不属于铁风按键 |
| 原版“切换步行／慢跑／奔跑”键 | 切换角色移动档位；铁风只同步结果，本机当前绑定为 `NUM6` |
| `Tab` | 打开库存并释放鼠标，同时保留 V 模式控制和镜头距离 |
| `Alt` | 普通 V 战斗中继续锁定镜头；特定 UI 路径释放鼠标 |

v117 删除了上游遗留的 Ctrl 第三人称镜头开关。V 模式只有一套连续的越肩／第一人称镜头；`F` 与滚轮负责切换第一人称，`P` 不再使用。V 模式按 F 时只消费与它冲突的原版 `focus_char` 回中事件；退出 V 后，原版 F 行为恢复。Ctrl 不再把仍受 WASD 控制的人物切回原版俯视镜头，但仍可供游戏菜单、Ctrl+点击和用户自行绑定的其他命令使用。为避免同键触发视角和格挡，关闭方向战斗后的键盘格挡默认迁到 `Q`；右键方向格挡不变。

v118 删除旧 `SpeedCycle=X`、`ManualAttack=Z` 配置及其轮询、状态和降级入口。`Z=speed_1`、`X=speed_3` 现在始终只由 Kenshi 原版处理；铁风继续监听原版 `cycle_run_speed`，把步行／慢跑／奔跑选择同步给受控角色。

攻击映射按箭头和刀刃的实际运动方向定义：鼠标右移显示右侧向心 `←`，武器从右向左；鼠标左移显示左侧向心 `→`，武器从左向右；上移显示 `↓` 并下劈；下移显示 `↑` 并突刺。v56 将格挡与攻击的水平语义拆开：鼠标右移仍显示右侧 `←`，但选择原版右侧格挡；鼠标左移仍显示左侧 `→`，但选择原版左侧格挡。上下格挡不翻转。方向采样使用短窗口、径向死区和对角线迟滞；按住左键后的第一下手势即选中方向，之后小幅回中或视角微漂不会在松开前翻转箭头，想换向需要一次明显更大的鼠标移动（v38 粘滞选向）。停止移动鼠标后选向保留约 0.8 秒供下次按压继承。将 `DirectionalCombat = false` 可切回 `E` 攻击、`Q` 格挡，但 V 仍负责进入手动战斗。v116 已完整移除旧手动闪避输入；`Shift+W/A/S/D` 只作普通移动。

## 当前战斗规则

- 准星明确指向角色时可构成蓄意攻击；空处或非角色对象只会原地空挥。
- 敌对目标只由准星/锁定选择“打谁”；v55 不再用铁风的武器距离、45°/55° 扇区或最多 4 人扫描决定敌人是否命中。提交后进入原版 `STARTUP → CHOP_WEAPON`，由 Kenshi 的攻击区、招式、命中、闪避、格挡、伤害、护甲和 XP 链完整判断。
- v53 的 `CombatClass::weaponReach()` 只继续服务自由空挥招式筛选和诊断。v51 的错位成员会造成全场命中；不得再把任何单一长度字段直接当作中立命中半径。
- v54 的身体投影和 25° 中立窄扇区继续保留：只在原版武器范围内选择正前方最近的非队友中立人物。玩家小队仍绝不成为目标，远处和侧面人物不参与。
- v57 在左键按下时、方向划动转动镜头之前保存准星下的中立目标，并把目标随唯一一击缓存一起保存。v64 继续用该逻辑选择“打谁”，但中立目标不再走自由动画的手工 impact。
- v67 删除近战的 focused/unprovoked AI 任务入口。左键释放当帧直接调用角色自身的原版 `AttackState::initialiseAttack(target)`；初始化成功才进入 `CHOP_WEAPON`，AI 不再决定等待、靠近、转向、出刀时机或下一击。
- v80 不再让“释放瞬间是否正好锁中”决定整刀能否产生伤害：没有精确目标但 2×准星范围内存在敌人时，最近敌人只作为原版 AttackState 的执行载体；铁风不自动转向、不靠近、不扩大命中区，实际砍到谁仍由原版攻击区决定。只有该范围内确实没有敌人时才使用纯动画空挥。
- v81 将活片段恢复门统一放到所有攻击退出观察点之前。原版状态若被提前改回 DECISION，但同一 technique 的动画仍明确播放且未完成，会恢复一次 CHOP；敌人真实命中导致的原版受击反应不会被恢复逻辑覆盖。
- v82 区分“原版伤害阶段完成”和“视觉动作完整播放”：`currentTechniqueHasFinished` 后不再继续执行攻击区或伤害，但保留同一原版动画片段自然播放收招；真实 clip 到尾才恢复自由控制。未命中和命中使用相同动作完整性，不靠固定时长。
- v83 规定原版攻击与自由格挡不能同时占用战斗动画层：命中阶段前的右键只等待；命中阶段后先安全退出 CHOP，本帧不播放格挡，下一游戏帧确认攻击已收权后才进入格挡。
- v68 证明直接初始化的攻击没有高层任务继续调度：状态对象调用虽每帧执行，但它不是动画段/impact 的执行入口，攻击计时固定在 0.200。v69 改为限定调用非虚的原版基类 `CombatClass::update(frameTime)`；CHOP 会直接进入 `CombatClass::attackState`，而不会进入 `CombatClassAI::update`。
- 游戏本帧未调度 `CombatClass::go` 时仍由主循环补执行一次，同一帧严格去重；原版攻击区、动画时间轴、命中、格挡、闪避、伤害、护甲和 XP 是唯一结算来源，没有玩家侧 AI 走位或连击入口。v108 将中立敌对改成单一提交点：直接 AttackState 初始化时产生的提前 `attackingYou` 通知会被延后，挥空、闪避和被格挡都不建立局部敌对；只有受害者真正进入原版 `_getHit` 后，才一次性提交 campaign、awareness 和受害者响应。盟友没有插件强制攻击任务，而是在完整世界事件提交后按 Kenshi 原版关系、感知、距离和 AI 决定是否支援。
- 原版拒绝当前目标或当前方向时，本次不会启动目标攻击，也不会交给 AI 重试或寻路；画面降级为既有的无伤害空挥。已经进入 CHOP 的动作仍完全跟随原版状态和时长。
- 玩家队伍成员在目标选择和伤害结算两处都被排除。
- 中立目标过远时只会空挥；敌对攻击是否具备攻击条件由原版战斗状态机判断。铁风仍在一次已授权攻击结束后收回控制，禁止无输入自动连击。
- 招式必须与锁定方向一致；当前武器/技能没有对应招式时不会偷偷播放其他方向。松开无效方向不出刀，也不会锁定后续输入。
- v99 正式覆盖空手武术。空手时原版 `weaponReach()` 的 0 是合法值，铁风会把它原样交给 Kenshi 的 `chooseAttack`，因此武术等级、负重、伤势和原版 technique 条件继续决定可用招式；不会套用刀剑距离，也不会凭空补出角色尚未解锁的四向动作。绿色仍表示原版 chooser 实际提供了该方向，白色表示本次未确认或没有该方向动作。
- 武术攻击敌人仍走原版 `AttackState` 的攻击区、格挡、闪避、伤害、护甲和 XP。攻击中立时，空手没有可供插件使用的武器距离，所以只允许准星明确覆盖身体来建立攻击意图；这不是命中许可，距离不足仍由原版判空，并且只有真实 `_getHit` 才触发敌对。
- 当前挥刀或收招期间可缓存一次下一击；恢复时间结束后才提交。
- `自动格挡（AI 决定方向）` 关闭时，玩家按住右键并选择方向；有效请求、可防御前方和来袭方向匹配后立即具备格挡资格，不等待画面姿势完全抬起，也没有额外“完美格挡”毫秒窗或奖励蓝光。命中仍返回原版 `HIT_SWORD`，由 Kenshi 播放火花、声音并处理经验。开启自动格挡后仍必须由玩家按住右键请求防御，只有方向与具体防御招式交给原版 AI，松开即停止；原版返回空就正常挨打。两种模式请求有效期间 WASD 不产生位移，松开立即恢复。
- v102 取消 v101 的常驻交互层。靠近并面向非敌对角色、队友或昏迷／死亡角色时自动出现黄色 `交互：名字` 提示；按 `E` 只打开该目标的原版上下文菜单，菜单关闭即恢复准星与战斗。攻击、格挡或受击期间不会打开，右键无论按多久都只格挡。
- 空格仅暂停世界时间，不再被当成菜单占用鼠标；V 模式越肩／第一人称在暂停时仍可转动视角并用滚轮调整远近。真正的 Esc、库存、对话、地图和上下文菜单仍释放光标并暂停相机输入。
- 断腿爬行（`PS_CRIPPLED`）、装死（`PS_PLAYING_DEAD`）和仍有意识的倒地敌人可以被准星与近敌载体选择；真正死亡或 `PS_KO` 仍不可选。铁风只允许它们进入原版 `AttackState`，实际刀路、范围、格挡与伤害仍由原版判定。
- 准星周围只显示当前选中的一个向心箭头，但上、下、左、右四个方向都能显示。绿色只表示当前武器、技能和单双手状态具备该方向的原版动作，不表示任何目标处于命中距离；缺少该方向动作或尚未确认时为白色。目标和距离不限制玩家挥空气。箭头不为格挡变蓝。四向使用同一程序几何旋转生成的独立 64×64 纹理；笔画约 3 px，视觉中心半径为 258 像素。v89 按实战输入把纵向原始计数校正为 1.25 倍，并缩小对角迟滞，使上下选择与左右的操作难度更接近；不是随机四等分，最终方向仍完全来自玩家手势。
- 被命中后的控制权完全跟随原版 `_getHit(..., stumble)` 与 `STUMBLE/REACTION_BLOCK` 状态：v45 不再把原版受击入场的 `STARTUP → STUMBLE` 误当成 AI 攻击起手，并在 V 自由攻击中恢复原版受击调用所需的战斗标志。轻受击不会被铁风固定延长，真实僵直一直持续到原版状态结束；期间的新攻击、格挡和方向输入直接丢弃。v90 进一步区分“玩家攻击 STARTUP”和“受害者 STARTUP → STUMBLE”：攻击途中被命中时立即释放铁风的旧攻击所有权。v109 为切磋等第三方战斗控制器补充一个窄兜底：只有原版已经排队 `STARTUP → STUMBLE/REACTION_BLOCK`、且本帧没有调度该角色的 `CombatClass::go()` 时，才补执行一次原版 `go()`；不设置僵直时长、不直接写反应状态，也不放行普通 AI 决策。退出 V 仍只清铁风的攻击账本和缓存，不写原版状态、不截断原版动画。
- v110 导出只读接口 `IronwindCombat_IsManualControlActive(Character*)`，供其他插件识别某个角色是否正由 V 模式拥有。铁风不保存、恢复或猜测第三方任务；调用方可在真实 V 退出边沿恢复自己的高层任务，避免按帧探测“停手”或使用定时补单。
- 原生受害者 `_getHit` 回调确认真正命中后，紧贴准星四个对角会显示四条红色斜线，组成断开的红色 X；v84 将笔画略微加粗并把初始不透明度限制为约 82%，随后在约 1000 ms 内淡出。仅有候选 verdict、空挥、超距、格挡和闪避不会触发。
- 姓名和生命面板只显示当前准星焦点／锁定对象，是观察 UI，不是伤害资格。v119 保持两行布局：上排“血／头／胸／腹”，下排“左臂／右臂／左腿／右腿”，并把每条由短色块改为更紧凑的 `38×5 px` 细长条。每条直接使用 Kenshi 原版医疗皮肤和真实状态分段：有机健康为原版绿，骨人／机械肢体为原版蓝，钝伤为灰，未处理切割伤为红，已包扎／修理的切割伤为黄，夹板为白色覆盖，机械磨损显示原版碾碎色。条长读取 `flesh`、`fleshStun`、`bandaging`、`juryRigging`、`wearDamage` 与原版有效最大值；不存在的部位隐藏。
- 原生 `attackingYou` 来袭事件只作为自动格挡的内部状态。v121 已删除铁风自制的敌人手部／武器发光纹理、颜色分级和设置项；原版 `HIT_SWORD` 的格挡碰撞火花、声音与经验仍由 Kenshi 自己处理。
- 空处和红名是白准星；中立是黄准星；友方是绿准星。不换成原版黄/绿箭头。只有对准有玩家对话包的人才会把准星换成对话气泡。
- 挥刀不应被固定毫秒数截断；正常结束依据实际动画状态，保护超时只处理对象丢失或卡死。
- v116 没有玩家主动闪避系统：旧 Q／Shift+方向输入、配置、状态、招式副本、动画注入、位移、技能加成钩子和诊断事件均已删除，等待重新设计。Kenshi 原生敌人闪避以及自动格挡请求中原版 chooser 返回的原生闪避仍保留，不属于铁风主动闪避功能。

## 镜头、库存与设置

- 越肩滚轮距离最远为 120；室内临时限制到最多 35，并进行墙体避让。
- v89 在 V 模式期间把 3D 音频监听器的位置锚到受控角色自身 `audioData.Position`，并仅对该受控角色绕过原版在 Wwise 发布前执行的视觉相机距离拒绝。监听器朝向仍跟随当前视角，因此左右、前后定位保持相机语义；其他角色、环境声、V 外行为、全局音量和音源衰减参数保持原版。退出 V、读档或角色失效后立即停止两层覆盖。
- 向下看时相机沿完整俯仰向量绕肩部枢轴移动；俯角接近当前约 74° 上限时，水平后距会从配置距离缩短到约 27%，镜头自然落到头顶上方。这不是本次墙体碰撞拉近（现有日志未出现 `hit=1` 或距离被夹到最小值），后续应在“限制最大下俯角”和“保持最小水平后距”之间实机选型。
- 第一人称 FOV 独立于越肩视角。默认/重置值为 90°，允许范围 50°–110°；本机 INI 可保存其他用户值。
- V 模式库存打开时释放鼠标，但保留 WASD 与当前越肩距离；无方向输入时角色应原地停住。
- 游戏“选项 > 铁风执刃”只展示常用按键与 11 个玩家设置：移动倍率、自动格挡、准星目标夹角、姓名／血条、越肩高度、第一人称灵敏度／FOV／头部隐藏／眼位高低／眼位前后和详细日志。原版步行档位不在此重复；仍有实际兼容价值的攻击缓冲、键盘格挡、镜头裁剪、特殊种族和动作眼位参数继续保留在 INI，供个人 DIY。节名和 INI 键名是程序接口，不可翻译。
- `VerboseLog = true` 时，诊断写入 Kenshi 根目录 `RE_Kenshi_log.txt`。定位完问题后可关闭。

## 证据边界与未完成系统

## 构建与部署

源码真源：`_moddev/BannerlordCombat/`。

```powershell
.\tools\ironwind.ps1 Check
.\tools\ironwind.ps1 DevFinish
.\tools\ironwind.ps1 Finish
.\tools\ironwind.ps1 UseStable
.\tools\ironwind.ps1 UseDev
.\tools\ironwind.ps1 SessionStart -Label vNN-test
.\tools\ironwind.ps1 AnalyzeLog -OpenReport
```

- `tools/ironwind.ps1` 是统一入口；命令说明见 `tools/README.zh-CN.md`。
- `build-local.ps1` 使用本机 Visual C++ 2010 x64 工具链生成 DLL、匹配 PDB 和 `BUILD-STAMP.json`。
- `DevFinish` 把本地开发版安装为独立的 `IronwindCombatDev.mod`，自动切到开发通道并显示 `[DEV] 铁风执刃`；Steam 正式版 `IronwindCombat.mod` 保持只读。
- `Finish` 只生成正式发布包和归档，不安装、不覆盖 Workshop 订阅版，也不改变当前启用通道。
- `UseStable`／`UseDev` 在两个身份之间互斥切换，保留其他 Mod 的加载顺序并备份 `mods.cfg`。
- `deploy-local.ps1` 校验构建指纹，按 Development／Release 通道从 `runtime/` 重建不同暂存目录并生成通道清单。
- `Analyze-IronwindLog.ps1` 自动切分实机会话、发现新事件、配对攻击链并以当前样本动态识别时长离群；报告不替代画面验证。
- 游戏运行时部署脚本会拒绝替换 DLL。
- 发布包位于 `package/IronwindCombat-actions-v<版本>.zip`。
- 安装前 DLL 备份位于 `backup/`。恢复原插件时退出游戏、取消铁风、再勾选原插件；Workshop 文件保持只读。

构建成功只代表静态与二进制检查通过。没有执行 [TESTING.md](TESTING.md) 的游戏内步骤时，交付说明必须标为“待实机验证”。
